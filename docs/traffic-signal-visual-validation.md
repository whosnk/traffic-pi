## 本轮实现

- Rust 控制桥声明 `traffic-pi-signal-visual-v1`，逐帧按当前相位绘制目标路口转向权限；新增路口聚焦和轮廓预览，保留原地图、Canvas 和 iframe 缩放。
- 真实治理使用右侧“当前治理”，历史记录单独切换。原配时、候选、两轮样本和实时信号分开保存；只有读回核对通过后才标记新配时生效。
- 真实信号单请求轮询，读取失败清空展示并请求关闭图层。任务结束清理图层与轮询。
- 原／新配时使用共用周期尺度，排队曲线以各轮已推进秒数对齐，未采样部分留空；汇总使用相同样本。
- 用户选择才产生执行授权；重复提交禁用。验证可在采样段结束后暂停观察，继续保留心跳与任务锁，执行时限仍计时。
- 没有合法候选时只读初筛同一次检测中的其他道路；用户改选才重启诊断。
- 治理期间保存并调整左右布局，结束或取消后恢复；等待选择与决策期间不恢复布局。

## 范围与限制

重庆交付场景没有被改为固定配时。测试中的固定配时只存在于独立浏览器窗口，用来验证真实引擎的应用与恢复；不代表当前每一处拥堵道路都有合法优化方案。自适应、无信号、下游阻塞或证据不足仍会结束诊断。实际相位变换及放行几何已检查；当前抽查路口没有覆盖所有可能的让行转向组合。

完整 300 秒双轮检查采用路口 1181、道路 484，原配时 30／15 秒，候选 35／10 秒。该次实际采样的目标排队与通过量均为 0，因此只证明执行、采样对齐和恢复有效，不能作为缓解拥堵的效果证据。

不接入高速治理、SUMO 联动或搜索优化算法。交互测试注入工具事件和 Agent 响应，未调用真实付费模型验证完整自然语言选工具过程。原有多项未提交改动仍保留。
